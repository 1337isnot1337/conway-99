## Coordinate mapping and normalization

The 550-vector is a constant coordinate followed by 549 ordinary,
unlabelled core-subgraph counts. These coordinates are nonnegative in
every actual graph. Induced counts are obtained from the exact integer
forms by division by `10! = 3628800`.

The probe checks equality of the old graph catalogue, automorphism orders,
and first 57 core indices. It also checks equality of the old injective
forms, zero dependence of old forms on new coordinates, and the exact
factor of ten between the old and new induced forms. This factor is
`10!/9!`; it is not a change in the underlying induced-count convention.

Consequently, fixing the first 58 coordinates really fixes the published
constant and order-nine core point. The alternative substitution fixes
coordinates `0,56,57` to `1,0,0`. The latter two are checked against the
two nine-vertex catalogue graphs with at least 17 edges: the rook and
broken-rook types. The exact acceptance check also requires both induced
counts to be zero.

## Exact preprocessing

Each induced-count inequality has the form

\[
c+\sum_j a_jx_j\ge0,\qquad x_j\ge0.
\]

Fixed coordinates are substituted with Python integers. Division by the
positive gcd preserves the inequality. If `c=0` and every remaining
coefficient is negative, nonnegativity forces every corresponding
coordinate to zero. The implementation's coefficient lists contain no
zero entries, so its test with `a_j <= 0` is equivalent. Repeating this
operation is sound. A negative constant with no remaining variables is
an exact contradiction. A nonnegative constant with only nonnegative
coefficients is redundant and can be dropped. Deduplication preserves
all remaining inequalities.

Neither saved run forced an additional coordinate to zero or found an
exact preprocessing contradiction.

## Numerical search and exact acceptance

The search divides each retained row by the sum of the absolute values
of its variable coefficients and maximizes a common normalized margin.
This is only a way to propose a point. The reported numerical status and
margin are not proofs.

The numerical search does not explicitly impose all residual extension
equalities or integrality congruences. This does not invalidate its
acceptance rule: a rounded proposal is accepted only after checking
nonnegative integer coordinates, nonnegative integral induced counts,
all level totals, all 180,445 original extension equations, and the two
zero induced counts. The multiplication uses object arithmetic, so the
integer count check does not rely on fixed-width products.

The unreduced identities have the correct count normalization. If `c_H`
is the number of induced copies of an unlabelled parent `H`, then
`|Aut(H)| c_H` counts its labelled induced embeddings. For each embedding,
an added vertex has respectively

\[
99-|H|,\qquad14-\deg_H(i),\qquad
2-A_H(i,j)-|N_H(i)\cap N_H(j)|
\]

choices when no vertex, one vertex, or two vertices are required as
neighbors. Summing allowed extension masks counts the child embeddings
with the factors `|Aut(child)|`. These are the equations generated by
`subgraph_counts.identities`. Removing their common integer factor and
duplicate equations is valid.

An original-equation failure in `verify_integer` raises an assertion
instead of saving a candidate-failure record. Such a failure would be an
operational interruption, not an exclusion. Neither saved run reached
that stage.

Each run requested 30 solver seconds. Their reported solver times were
about 31.6 and 31.9 seconds. The catalogue has 48,965 types, including
42,430 of order ten; the reduction has 492 new core coordinates.

No induced-count vector was saved. Therefore there was no witness for an
independent direct extension-equation replay, and no nine-rook subset
positive control was run in this audit.

Even a future accepted point would be a count assignment, not a graph.
A fixed-prefix witness would preserve the previously checked finite
order-nine moment blocks. A free-prefix witness could change those
blocks and would need them checked again. Neither numerical probe
constructs or verifies new order-ten moment blocks.

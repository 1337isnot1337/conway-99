# Exact consistency of the order-ten count reduction

All 180,445 original extension equations reduce identically to zero in
the 549 ordinary-core coordinates. Every induced-count form has integer
coefficients, and every labelled ordinary-count form is coefficientwise
divisible by its graph's automorphism order. The order-ten reduction
therefore needs no additional linear equality or congruence constraints.

This is an algebraic statement about the existing reduction. It does
not prove that any proposed count vector is nonnegative, satisfies
moment inequalities, or comes from a graph.

## What was checked

The audit reads the exact cache generated by `core_counts.reduce_counts`
on the 48,965-type catalogue through order ten. Its common induced-count
denominator is `10!=3628800`. The audit checks every coefficient before
dividing by this denominator. It separately checks the labelled
ordinary-count forms modulo each automorphism order.

After these checks, each original extension equation is substituted into
the integral induced-count forms. Its resulting 550-entry coefficient
vector, including the constant, is exactly zero. This verifies the
identities for every value of the core coordinates, not only for a
sample count vector.

| Quantity | Exact value |
|---|---:|
| Induced types | 48,965 |
| Ordinary core variables | 549 |
| Original equations checked | 180,445 |
| Nonzero reduced equations | 0 |
| Additional ordinary-count congruences | 0 |
| Largest absolute integral count coefficient | 462,437,999,100 |
| Largest equation absolute-sum bound | 19,636,823,580,323,796 |
| Signed 64-bit upper limit | 9,223,372,036,854,775,807 |

The cache starts with arbitrary-precision integers. Conversion to
fixed-width storage is checked back against every original coefficient.
Before each equation is evaluated, the sum of absolute term bounds is
checked against the signed 64-bit limit. This bounds every intermediate
sum as well as its final value. No floating-point sign or zero test is
used.

The result explains why an integer core vector automatically has integral
induced counts in this reduction. Nonnegativity still needs a separate
check. The archived numerical proposals do not pass that check merely
because this audit passes.

## Replay

First regenerate the exact cache using the recipe in
[the order-ten probe note](grid_free_order10_probe.md), or reuse that
unchanged cache. Then run:

```sh
.venv/bin/python experiments/workspace/order10_reduction_audit.py \
  --cache /absolute/path/to/order10-reduced.pickle \
  --output /tmp/order10-reduction-audit.json
```

The [source](../../experiments/workspace/order10_reduction_audit.py)
and [saved result](../../experiments/logs/moments-and-counts/order10-reduction-audit.json)
bind the cache and verifier by SHA-256.
